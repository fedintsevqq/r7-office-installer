# Установщик Р7-Офис Linux

Один скрипт ставит Р7-Офис на шесть систем: Debian 12, Debian 13, Astra Linux, Альт Linux, РЕД ОС и РОСА «Хром». Сам определяет, где запущен, сам подбирает имена пакетов, сам чинит запуск под Wayland — и предупреждает, если вы скачали пакет не под свою ОС.

Версия 2.2 добавила то, чего не хватало для тестового парка машин: историю установок, HTML-отчёты, диагностику версий зависимостей, отключение засыпания экрана на время долгих прогонов и самообновление скрипта.

## Быстрый старт

**Положите дистрибутив Р7 (`.deb`(Debian), `p8.rpm`(Alt), `.el8`(RedOS)) в папку «Загрузки».** Скрипт скачается туда же — оба файла должны лежать рядом, в одной папке.

Важно: у Р7 разные сборки под разные ОС, и имя файла не всегда это выдаёт на глаз. Берите пакет с сайта именно под вашу систему — скрипт теперь это проверяет сам и предупредит, если сборка не та (подробности ниже, в разделе [«Проверка сборки пакета»](#проверка-сборки-пакета)).

Дальше скопируйте блок под свою систему и вставьте в терминал целиком.

### 🐧 Debian 12

```bash
cd "$(find /home -maxdepth 2 -type d \( -name "Загрузки" -o -name "Downloads" \) -print -quit 2>/dev/null || echo ~)"
curl -fsSLO https://raw.githubusercontent.com/fedintsevqq/r7-office-installer/main/install-r7.sh
chmod +x install-r7.sh
sudo ./install-r7.sh --os debian12 -l
```

### Система неизвестна

Уберите `--os`, скрипт определит сам:

```bash
cd "$(find /home -maxdepth 2 -type d \( -name "Загрузки" -o -name "Downloads" \) -print -quit 2>/dev/null || echo ~)"
curl -fsSLO https://raw.githubusercontent.com/fedintsevqq/r7-office-installer/main/install-r7.sh
chmod +x install-r7.sh
sudo ./install-r7.sh -l
```

Первая строка переходит в «Загрузки». Флаг `-l` берёт самый свежий пакет из папки; уберите его, чтобы выбрать версию в меню.

Если пакета ещё нет, скачайте его по ссылке:

```bash
sudo ./install-r7.sh -u https://ссылка-на-пакет
```

Полностью без вопросов:

```bash
sudo ./install-r7.sh -f -y
```

Вместо `--os` можно взять готовую обёртку — `update-r7-redos.sh`, `update-r7-rosa.sh` и остальные. Обёртки тонкие: вся логика в `install-r7.sh`, поэтому класть их нужно рядом с ним.

## Аргументы командной строки

**Установка**

| Аргумент | Что делает |
|---|---|
| `-v, --version ВЕРСИЯ` | поставить конкретную версию: `-v 8.1.0-1234` или просто `-v 2815` |
| `-l, --latest` | взять самый свежий файл из папки |
| `-f, --fast` | fast-lane: зависимости плюс свежая версия |
| `-u, --url URL` | скачать пакет по ссылке и поставить |

**Проверка целостности**

| Аргумент | Что делает |
|---|---|
| `--check` | проверять контрольную сумму |
| `--md5 ХЭШ` | сверить с MD5 из документа Word |

Подпись самого пакета (`rpm -K` / `dpkg-sig`) скрипт проверяет автоматически, без отдельного флага — результат виден в выводе установки, в истории и в отчёте.

**Зависимости и диагностика**

| Аргумент | Что делает |
|---|---|
| `--list-deps` | показать зависимости для этой ОС: стоит / есть в репозитории / нет |
| `--check-deps` | то же самое, но с версиями: установлена / версия-кандидат / вердикт — не подключает сторонние репозитории |
| `--install-deps` | поставить только зависимости |
| `--health` | диагностика системы |
| `--verify` | smoke-тест: реально ли соберутся зависимости бинарника (`ldd`), без переустановки |
| `--fix-wayland` | починить запуск под Wayland |
| `--remove` | меню удаления |

**История и отчёты**

| Аргумент | Что делает |
|---|---|
| `--history [N]` | последние N установок и удалений, по умолчанию 10 |
| `--report` | открыть последний HTML-отчёт об установке |
| `--report list` | список сохранённых отчётов |
| `--report json` | последний отчёт в JSON — в stdout, для CI |

**Обновление скрипта**

| Аргумент | Что делает |
|---|---|
| `--upgrade` | обновить сам `install-r7.sh` до последней версии с GitHub |
| `--upgrade-check` | только проверить, есть ли обновление, ничего не меняя |

**Простой экрана** (для ночных прогонов и soak-тестов)

| Аргумент | Что делает |
|---|---|
| `--no-idle` | не трогать засыпание и блокировку экрана |
| `--restore-idle` | вручную вернуть настройки экрана, если предыдущий запуск прервали жёстко и авто-восстановление не сработало |

**Режимы**

| Аргумент | Что делает |
|---|---|
| `--gui` | графический режим через zenity |
| `--os ПРОФИЛЬ` | задать ОС вручную: `debian12`, `debian13`, `astra`, `alt`, `redos`, `rosa` |
| `--dir ПУТЬ` | папка с дистрибутивами |
| `--config ПУТЬ` | свой конфиг вместо `/etc/r7-installer.conf` |
| `--dry-run` | показать команды, ничего не делая |
| `-y, --yes` | не задавать вопросов |
| `--no-color` | вывод без цветов |
| `-h, --help` | справка |

## Примеры

```bash
# свежая версия с проверкой MD5
sudo ./install-r7.sh -l --md5 a1b2c3d4e5f6...

# конкретная версия
sudo ./install-r7.sh -v 8.1.0-1234

# посмотреть, что скрипт собирается делать, ничего не устанавливая
sudo ./install-r7.sh -l --dry-run

# дистрибутивы лежат на сетевом диске
sudo ./install-r7.sh --dir /mnt/share/r7 -l

# что не так с системой
sudo ./install-r7.sh --health

# после установки Р7 под Wayland показывает пустое окно
sudo ./install-r7.sh --fix-wayland

# версии зависимостей: что устарело, чего нет в репозитории
sudo ./install-r7.sh --check-deps

# последние 20 установок на этой машине
sudo ./install-r7.sh --history 20

# ночной прогон в Jenkins: экран не гаснет, вопросов нет
sudo ./install-r7.sh -f -y --no-idle

# проверить обновление скрипта, не устанавливая его
sudo ./install-r7.sh --upgrade-check
```

## Проверка сборки пакета

Р7 собирает под каждую RPM-систему отдельный пакет. Имя файла выглядит похоже везде (`r7-office-ВЕРСИЯ.ТЕГ.x86_64.rpm`), но тег в середине имени говорит, под какую ОС собраны зависимости внутри:

| Тег в имени файла | Для какой ОС | Пример |
|---|---|---|
| `.p8`, `.p9`, `.p10`, `.p11` | Альт Linux | `r7-office-2024.4.1-625.p8.x86_64.rpm` |
| `.r8`, `.r9` | РОСА | `r7-office-2026.2.2-2548.r9.x86_64.rpm` |
| `.el7`, `.el8` | РЕД ОС | `r7-office-2024.4.1-630.el8.x86_64.rpm` |
| `~astra[-signed]` | Astra Linux (.deb) | `r7-office_2024.4.1-630~astra-signed_amd64.deb` |

Если поставить «не свою» сборку, пакетный менеджер упрётся в зависимости — например, попытка поставить пакет с тегом `.r9` (собран под РОСА, там библиотеки называются `lib64gtk+2.0_0`, `lib64x11_6` и так далее) на РЕД ОС даёт ровно такую ошибку:

```
nothing provides fonts-ttf-dejavu needed by r7-office-2026.2.2-2548.r9.x86_64
nothing provides lib64gtk+2.0_0 needed by r7-office-2026.2.2-2548.r9.x86_64
```

Это не сломанный репозиторий и не повод чинить список зависимостей руками — просто скачан не тот файл. Начиная с версии 2.1 скрипт узнаёт тег в имени файла, сверяет с текущей ОС и переспрашивает перед установкой, если они не совпадают. При автоматизации (`-y`, `-f`) проверка не блокирует установку, а только пишет предупреждение в лог — так что при массовом разворачивании стоит один раз вручную убедиться, что в папке лежат правильные пакеты.

## Wayland в Debian 13

Debian 13 по умолчанию поднимает сессию GNOME на Wayland. Р7-Офис построен на Qt и CEF — под чистым Wayland он либо не стартует, либо рисует пустое окно и теряет ввод с клавиатуры.

Скрипт решает это так:

1. Определяет тип сессии через `loginctl`, переменные окружения и сокеты в `/run/user/UID/`. Работает даже из-под `sudo`, когда переменные пользователя недоступны.
2. Ставит XWayland — прослойку, которая пускает X11-программы внутрь Wayland.
3. Кладёт обёртку `/usr/local/bin/r7-office-x11`. Она выставляет `GDK_BACKEND=x11`, `QT_QPA_PLATFORM=xcb`, убирает `WAYLAND_DISPLAY` и запускает Р7 через XWayland.
4. Копирует ярлык в `~/.local/share/applications` и подменяет в нём команду запуска на обёртку. Пользователь запускает Р7 из меню приложений как обычно и ничего не замечает.

Всё это происходит само при установке на Wayland-сессии. Отдельно можно вызвать `--fix-wayland`.

Если не помогло — выберите на экране входа сессию «GNOME на Xorg». Это запасной вариант, а не поломка скрипта.

## Оптимизация RDP в РЕД ОС

Р7-Офис по удалёнке тормозит: перерисовка окна идёт рывками. Скрипт правит `/etc/xrdp/xrdp.ini`:

- `tcp_send_buffer_bytes=33554432` и `tcp_recv_buffer_bytes=33554432` — буферы побольше, картинка ровнее;
- `max_bpp=16` — меньше цветов, заметно меньше трафика;
- `crypt_level=none` — снимает шифрование канала.

Про последний пункт честно: **`crypt_level=none` отключает шифрование RDP**. В доверенной локальной сети это нормальный размен скорости на защиту. Через интернет так делать нельзя. Поэтому скрипт спрашивает подтверждение, а исходный файл сохраняет в `xrdp.ini.r7-backup` — откатить можно пунктом `[P]` в меню.

На остальных системах этот блок не выполняется.

## Конфиг-файл

Для парка машин можно не передавать одни и те же флаги каждый раз, а положить `/etc/r7-installer.conf`:

```ini
# комментарии — через решётку
DOWNLOAD_DIR="/opt/r7-dist"
ASSUME_YES=true
REQUIRE_MD5=true
SKIP_RDP=false
ENABLE_REPORT=true
ENABLE_HISTORY=true
ENABLE_IDLE_CONTROL=true
UPGRADE_URL="https://raw.githubusercontent.com/fedintsevqq/r7-office-installer/main/install-r7.sh"
```

Приоритет источников: аргументы командной строки → переменные окружения (`R7_LOG`, `R7_STATE`, `R7_DIR`) → конфиг → умолчания. То есть `-y` в командной строке всегда победит `ASSUME_YES=false` в конфиге, а конфиг — победит умолчание.

Скрипт разбирает файл построчно, без `source` и без `eval`: `/etc` доступен на запись не только администратору, а `source` выполнил бы из конфига любой bash-код от root. Проверяются ещё и права на сам файл — владелец должен быть root, запись разрешена только ему. Конфиг с более широкими правами скрипт целиком проигнорирует и предупредит об этом.

Свой путь к конфигу — через `--config /путь/к/файлу`. Какой конфиг подхвачен (если подхвачен), видно в `--health`.

## Простой экрана: ночные прогоны и Jenkins

Гаснущий или блокирующийся экран может оборвать RDP/VNC-сессию раньше, чем скрипт закончит долгий прогон — актуально для soak-тестов и ночных серий установок.

Перед началом работы скрипт сохраняет текущие настройки простоя и отключает их:

| Окружение | Чем отключается |
|---|---|
| X11 (Debian, Astra, Альт/РЕД ОС/РОСА с X11-сессией) | `xset s off` / `-dpms` / `s noblank` |
| GNOME/Wayland (Debian 13, РЕД ОС, РОСА) | `gsettings` — idle-delay и блокировка экрана |
| Xfce (бывает на Альте) | `xfconf-query` — dpms-enabled |
| Текстовая консоль | `setterm` |

Настройки возвращаются на выходе — по `Ctrl+C` тоже, не только при обычном завершении. Если предыдущий запуск прервали жёстче (`kill -9`) и авто-восстановление не успело сработать, верните всё вручную:

```bash
sudo ./install-r7.sh --restore-idle
```

Отключить эту часть целиком — флагом `--no-idle` или ключом `ENABLE_IDLE_CONTROL=false` в конфиге. Xset/gsettings/xfconf-query вызываются от имени реального пользователя, а не root — иначе они просто не достучатся до чужой графической сессии.

Для консоли (`setterm`) честно: прочитать текущие настройки нечем, поэтому восстанавливаются не буквально прежние значения, а разумные умолчания (10 минут). Это единственное место, где восстановление не один в один.

## Проверка версий зависимостей

`--list-deps` показывает, стоит пакет или нет. `--check-deps` — то же самое плюс версии:

```bash
sudo ./install-r7.sh --check-deps
```

Для каждой зависимости: что установлено, что предлагает репозиторий, вердикт — актуальна, устарела, не установлена, недоступна. Версии читаются штатными командами каждого пакетного менеджера (`dpkg-query`, `rpm -q`, `apt-cache policy`, `dnf list`).

Одно принципиальное ограничение: скрипт **не подключает и не предлагает подключить сторонние репозитории**. РЕД ОС ФСТЭК и Astra ЗПС/МКЦ — сертифицированные конфигурации, посторонний репозиторий может вывести систему из сертифицированного состояния. Максимум, что делает скрипт — называет пакет, который нужен.

## История установок и отчёты

Каждая установка и удаление попадают в `/var/lib/r7-installer/history.log` — по одной JSON-записи на строку (JSON Lines, не массив: так лог можно дописывать, не перечитывая целиком). Посмотреть:

```bash
sudo ./install-r7.sh --history        # последние 10
sudo ./install-r7.sh --history 50     # последние 50
```

В каждой записи: дата, ОС, пакет, версия, статус (успех / ошибка / отменено), результаты проверки MD5, подписи пакета и smoke-теста, время выполнения, пользователь.

После каждой установки и после `--check-deps` в `/var/lib/r7-installer/reports/` сохраняется самодостаточный HTML-отчёт (плюс тот же результат в JSON рядом, для CI) — со сводкой, таблицей зависимостей и последними строками лога. Путь печатается сразу:

```
📊 Отчёт сохранён: /var/lib/r7-installer/reports/install-20260826_143211.html
```

```bash
sudo ./install-r7.sh --report          # открыть последний
sudo ./install-r7.sh --report list     # список всех
sudo ./install-r7.sh --report json     # последний — в JSON, для Jenkins
```

Открывается отчёт не от root — от имени реального пользователя (`xdg-open`), иначе браузер либо не запустится, либо насуёт root-овых файлов в чужой профиль. `--dry-run` ничего не пишет ни в историю, ни в отчёты: он и так ничего не делал.

## Обновление скрипта

```bash
sudo ./install-r7.sh --upgrade-check   # только проверить
sudo ./install-r7.sh --upgrade         # проверить и обновить
```

Скрипт качает свежую версию с GitHub во временный файл, проверяет её (`bash -n` на синтаксис, наличие ожидаемых маркеров), сравнивает версию с текущей, сохраняет бэкап в `/var/lib/r7-installer/backups/` и только тогда заменяет себя — атомарно, через `mv`, а не построчной перезаписью поверх работающего процесса. Если любая из проверок не проходит, файл на диске остаётся прежним.

Только HTTPS. GPG-подписи у релизов пока нет — если понадобится, это следующий шаг.

## Что скрипт делает при установке

1. Определяет ОС, пользователя, тип графической сессии, свободное место. Отключает засыпание экрана (если не задан `--no-idle`).
2. Сверяет тег сборки в имени файла с текущей ОС — предупреждает, если пакет явно не под эту систему.
3. Проверяет подпись пакета (`rpm -K` / `dpkg-sig`, где применимо) и MD5, если вы его ввели. MD5 не совпал — установка отменяется.
4. Показывает данные пакета и ждёт подтверждения.
5. Ставит зависимости: проверяет каждую по репозиторию, отсутствующие необязательные пропускает.
6. Находит запущенный Р7 и предлагает закрыть. Даёт 10 секунд на нормальное завершение, потом спрашивает про принудительное.
7. Удаляет старую версию, ставит новую через штатный пакетный менеджер — тот сам подтянет зависимости пакета.
8. Проверяет, что пакет действительно встал, и что бинарник реально соберёт свои зависимости (smoke-тест через `ldd`).
9. Настраивает Wayland и RDP, если нужно.
10. Записывает результат в историю и сохраняет HTML-отчёт.

## Файлы, которые создаёт скрипт

| Путь | Что это |
|---|---|
| `/var/log/r7-update.log` | журнал всех действий и вывод команд |
| `/var/lib/r7-installer/deps-ПРОФИЛЬ.done` | отметка, что зависимости уже ставили |
| `/var/lib/r7-installer/rdp-optimized.done` | отметка про RDP |
| `/var/lib/r7-installer/history.log` | история установок и удалений (JSON Lines) |
| `/var/lib/r7-installer/reports/*.html`, `*.json` | отчёты об установках и проверках |
| `/var/lib/r7-installer/backups/*.sh` | резервные копии скрипта перед `--upgrade` |
| `/var/lib/r7-installer/idle-saved.state` | сохранённые настройки экрана — временный, до восстановления |
| `/usr/local/bin/r7-office-x11` | обёртка запуска под Wayland |
| `~/.local/share/applications/r7-office-desktopeditors.desktop` | ярлык под Wayland |
| `/etc/xrdp/xrdp.ini.r7-backup` | копия настроек RDP до правок |
| `/etc/r7-installer.conf` | необязательный конфиг (скрипт его читает, не создаёт) |

Если `/var/log` или `/var/lib/r7-installer` недоступны на запись, всё уедет в `/tmp`.

## Если что-то пошло не так

Сначала — диагностика:

```bash
sudo ./install-r7.sh --health
```

Она покажет: стоит ли Р7, какой версии, каких библиотек не хватает, что с графической сессией, сколько места на диске.

Если установка падает на зависимостях (`nothing provides ...`) — проверьте тег в имени файла пакета по таблице в разделе [«Проверка сборки пакета»](#проверка-сборки-пакета). Чаще всего дело именно в этом, а не в самом скрипте.

Дальше — HTML-отчёт последней попытки (`--report`) и история (`--history`): в них уже собраны MD5, подпись, smoke-тест и хвост лога, не нужно искать по крупицам.

Потом — журнал:

```bash
tail -50 /var/log/r7-update.log
```

Частые случаи разобраны в [docs/user-guide.md](docs/user-guide.md).

## Перенос с Windows

Скрипты написаны с переносами строк в формате Unix. Если файл прошёл через Windows-редактор и bash ругается `bad interpreter: no such file or directory` — переносы битые, лечится так:

```bash
sed -i 's/\r$//' install-r7.sh
```

## Старые скрипты

В папке `legacy/` лежат прежние версии для Debian 13, Astra и РЕД ОС. Они работают, но у них есть три общие проблемы, которых нет в `install-r7.sh`:

- код возврата берётся у `tee`, а не у `dpkg`, поэтому провалившаяся установка отчитывалась как успешная;
- зависимости искались через `dpkg -l | grep`, а это ловит совпадения по подстроке;
- имена пакетов зашиты жёстко, из-за чего список для Debian 13 не работает на Debian 12.

Держите их как архив, а пользуйтесь новым.
