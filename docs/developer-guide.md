# Руководство разработчика

Как устроен `install-r7.sh`, почему он написан именно так и как его дорабатывать.

---

## Главная идея

Раньше на каждую ОС был свой скрипт. Пять скриптов — это пятикратное дублирование меню, проверки MD5, очистки кэша и логирования. Правка в одном месте не доезжала в остальные четыре.

Между дистрибутивами реально различаются всего три вещи:

1. команды пакетного менеджера,
2. имена пакетов,
3. специфические доработки — RDP в РЕД ОС, Wayland в Debian 13.

Поэтому здесь один скрипт с профилями ОС. Общий код живёт один раз, различия вынесены в две функции: `dep_spec()` и слой `pm_*`.

---

## Структура файла

Скрипт читается сверху вниз, блоки идут в порядке зависимостей:

| Блок | Что делает |
|---|---|
| Настройки и цвета | пути, палитра, `setup_colors` умеет отключать цвет |
| Вывод и логи | `ok`, `warn`, `fail`, `step`, `run`, `run_v` |
| Аргументы | `show_help`, `parse_args` |
| Определение ОС | `detect_os`, `check_os_version`, `ver_ge` |
| Пакетный менеджер | `pm_*`, `pkg_*` — слой абстракции |
| Зависимости | `dep_spec`, `install_all_dependencies`, бэкпорт gconf |
| Окружение | пользователь, тип сессии, диск |
| Wayland | XWayland, обёртка, ярлык |
| RDP | только РЕД ОС |
| Контрольные суммы | `check_checksum`, `hash_equal` |
| Поиск пакетов | `find_packages`, `extract_version` |
| Установка | `install_package`, `install_pkg_file` |
| Обслуживание | кэш, удаление, диагностика |
| Меню и main | интерактив, режимы командной строки |

## Слой пакетного менеджера

Весь остальной код не знает, apt перед ним или dnf. Он вызывает эти функции:

| Функция | Назначение |
|---|---|
| `pm_update` | обновить индексы, срабатывает один раз за запуск |
| `pm_install ПАКЕТЫ...` | поставить из репозитория |
| `pm_install_local ФАЙЛ` | поставить локальный файл с зависимостями |
| `pm_remove ПАКЕТ` | удалить |
| `pkg_installed ПАКЕТ` | стоит ли пакет |
| `pkg_available ПАКЕТ` | есть ли пакет в репозитории |
| `pkg_pick "альт1 альт2"` | вернуть первое существующее имя из списка |
| `installed_version` | версия установленного Р7 |

Внутри каждой — `case "$PM"` на четыре ветки: `apt`, `apt-rpm`, `dnf`, `yum`.

### Почему установка идёт через менеджер, а не через dpkg / rpm

Старые скрипты делали `dpkg -i файл`, затем `apt install -f -y` для починки. Так тоже можно, но менеджер справляется лучше: `apt-get install ./файл.deb` и `dnf install ./файл.rpm` сами читают зависимости из пакета и тянут их из репозитория за один заход.

`dpkg -i` остался запасным путём — на случай, если apt споткнётся.

Важная деталь: apt и dnf принимают локальный файл только когда в пути есть слэш. Без него `apt-get install r7-office_8.1.0.deb` пойдёт искать пакет с таким именем в репозитории и не найдёт. Поэтому `install_package` приводит путь к абсолютному.

### Альт Linux и apt-rpm

У Альта редкое сочетание: пакеты `.rpm`, а менеджер — `apt-get`. Не dnf и не тот apt, что в Debian.

Основной путь — `apt-get install -y файл.rpm`. Если не сработал, включается запасной: `rpm_missing_requires` разбирает `rpm -qpR файл.rpm`, отбрасывает служебные строки (`rpmlib`, `rtld`, пути) и проверяет каждое требование через `rpm -q --whatprovides`. Что не нашлось — отдаётся apt-get по именам provides. Apt-rpm умеет резолвить и SONAME вида `libgtk-3.so.0`.

## Как задаются зависимости

Функция `dep_spec()` печатает строки в формате:

```
req|libgtk-3-0t64 libgtk-3-0
opt|fonts-crosextra-carlito
```

Слева критичность, справа — альтернативные имена через пробел.

`pkg_pick` перебирает альтернативы слева направо и берёт первое имя, которое существует в репозитории. Это ключевой приём: он снимает необходимость держать отдельные списки для Debian 12 и Debian 13.

Пример. В Debian 13 прошёл переход на 64-битный `time_t`, библиотеки переименовались: `libgtk-3-0` стал `libgtk-3-0t64`, `libasound2` стал `libasound2t64`. Astra Linux 1.7 живёт на старой базе, там имена без суффикса. Одна строка `req|libgtk-3-0t64 libgtk-3-0` покрывает все три случая — на Trixie найдётся первое имя, на Bookworm и Astra второе.

Тот же приём страхует от разночтений в именах пакетов Альта, где точное название может отличаться от версии к версии: `req|libcairo cairo` попробует оба.

Отсутствующие `opt`-пакеты просто пропускаются и попадают в сводку в конце. Отсутствующие `req` дают предупреждение, но не останавливают работу — менеджер всё равно подтянет их по зависимостям самого пакета Р7.

### Как добавить зависимость

Откройте `dep_spec()`, найдите нужную ветку (`deb`, `alt` или общая rpm) и допишите строку. Больше ничего менять не нужно.

Проверить результат:

```bash
sudo ./install-r7.sh --list-deps
sudo ./install-r7.sh --os alt --list-deps
```

## Определение ОС

`detect_os()` идёт по порядку от частного к общему:

1. `--os` из аргументов — приоритет выше всего;
2. `/etc/altlinux-release` или `ID=altlinux`;
3. `/etc/redos-release` или `ID=redos`;
4. `/etc/astra_version` или `ID=astra`;
5. `ID=debian` или наличие `/etc/debian_version`, дальше разбор номера версии;
6. запасной вариант — по наличию `dnf`, `rpm` вместе с `apt-get`, `dpkg`.

Порядок именно такой, потому что Astra и Альт — производные, и общая проверка на Debian поймала бы Astra раньше, чем сработала специфическая.

Debian 12 и 13 разводятся по `VERSION_ID`. Версии новее Trixie получают профиль `debian13`, старее Bookworm — `debian12`. Незнакомое значение уходит в `debian13` как в более современный.

`check_os_version` сверяет версию с минимальной поддерживаемой и на старой системе выводит предупреждение. Не блокирует — решение остаётся за администратором.

## Определение графической сессии

`detect_session_type()` — не самая очевидная часть. Проблема в том, что скрипт работает от root, а сессия принадлежит обычному пользователю. Переменные `XDG_SESSION_TYPE` и `WAYLAND_DISPLAY` под sudo обычно не видны.

Поэтому проверки идут каскадом:

1. `$XDG_SESSION_TYPE`, если он всё-таки есть;
2. `loginctl show-session -p Type` для сессии реального пользователя — самый надёжный способ;
3. сокеты `/run/user/UID/wayland-*`;
4. процессы `Xorg` и `Xwayland`;
5. наличие `$DISPLAY`.

Реального пользователя ищет `detect_real_user()`: сначала `$SUDO_USER`, затем `who` с фильтром по графическим сессиям, затем `logname`, затем первый каталог в `/home`. Это нужно и для сессии, и для путей к кэшу и ярлыкам — они лежат в домашней папке пользователя, не root.

## Как чинится Wayland

Р7-Офис использует Qt для окон и CEF для отрисовки документов. Оба под чистым Wayland ведут себя плохо: окно не получает содержимого, ввод не доходит.

Лечение — прогнать программу через XWayland, выставив X11-бэкенд:

```sh
export GDK_BACKEND=x11
export QT_QPA_PLATFORM=xcb
export CLUTTER_BACKEND=x11
export SDL_VIDEODRIVER=x11
export XDG_SESSION_TYPE=x11
unset WAYLAND_DISPLAY
```

Эти строки пишутся в `/usr/local/bin/r7-office-x11` (функция `create_x11_wrapper`), туда же подставляется найденный путь к бинарнику.

Сознательное решение: обёртка задаёт только переменные окружения и не передаёт Р7 никаких флагов вроде `--ozone-platform=x11`. Неизвестный аргумент программа может не понять и упасть, а переменные безопасны.

`create_wayland_desktop_entry` копирует системный `.desktop` в `~/.local/share/applications` и меняет в нём `Exec=` на обёртку. Пользовательский ярлык перекрывает системный по стандарту XDG, поэтому запуск из меню приложений идёт через обёртку. Системный файл не трогается — обновление пакета его перезапишет и ничего не сломает.

Пути к бинарнику и ярлыку ищутся перебором (`find_r7_binary`, `find_r7_desktop`), потому что в разных сборках Р7 они разные: `/usr/bin/r7-office`, `/opt/r7-office/desktopeditors/DesktopEditors` и другие варианты.

## Что исправлено против старых скриптов

**Код возврата брался у `tee`.** Конструкция `dpkg -i "$file" | tee -a "$LOG"` с последующим `$?` всегда возвращала успех `tee`, а не результат `dpkg`. Провалившаяся установка отчитывалась как успешная. Теперь в начале файла стоит `set -o pipefail`, а `run_v` возвращает `${PIPESTATUS[0]}`.

**Дополнительно проверяется факт установки.** `install_pkg_file` не верит коду возврата на слово и спрашивает у системы: `pkg_installed "$PKG_NAME"`.

**Проверка пакетов через grep по подстроке.** `dpkg -l | grep "^ii.*libgtk-3-0"` считает установленным `libgtk-3-0-dev` и вообще любой пакет, где встретилась эта строка. Заменено на `dpkg-query -W -f='${Status}'` и `rpm -q`.

**`dnf install -y` без аргументов.** В скрипте для РЕД ОС такая команда вызывалась «для проверки зависимостей» и не делала ничего.

**Жёсткие пути.** `DOWNLOAD_DIR="/home/administrator/Downloads"` работал ровно на одной машине. Теперь папка ищется перебором кандидатов, есть `--dir`.

**Резервная копия xrdp.ini перезаписывалась.** Каждый запуск копировал уже изменённый файл поверх бэкапа, и после второго прогона откатиться было некуда. Теперь копия создаётся только если её ещё нет.

**Один общий флаг зависимостей на все ОС.** Файл-отметка теперь свой для каждого профиля: `deps-debian13.done`, `deps-alt.done`.

## Отладка

`--dry-run` показывает команды, не выполняя их. Проходит весь путь скрипта, включая определение ОС и подбор пакетов:

```bash
sudo ./install-r7.sh -l --dry-run
```

`--os` позволяет проверить чужой профиль, не имея под рукой этой системы. Установка, конечно, не пройдёт, но списки пакетов и логика видны:

```bash
sudo ./install-r7.sh --os redos --list-deps
```

Проверка синтаксиса без запуска:

```bash
bash -n install-r7.sh
```

Пошаговая трассировка:

```bash
bash -x install-r7.sh --health 2>&1 | less
```

Отдельные функции можно вызывать напрямую, если отрезать последнюю строку с `main "$@"`:

```bash
sed '$ d' install-r7.sh > /tmp/r7lib.sh
source /tmp/r7lib.sh
extract_version "r7-office_8.1.0-1234_amd64.deb"
```

## Соглашения в коде

- Bash, а не sh: используются массивы, `mapfile`, `${PIPESTATUS[@]}`.
- Все внешние вызовы идут через `run` или `run_v` — так они попадают в журнал.
- Функции возвращают `0` или `1`, вывод для человека идёт через `ok` / `warn` / `fail`.
- Переменные в кавычках. Исключения намеренные: `kill $pids` и `for x in $1` внутри `pkg_pick`, где нужно разбиение по словам.
- Комментарии на русском, имена функций и переменных — английские.
- Сообщения пользователю без жаргона: не «dependency resolution failed», а «не удалось установить: libgtk-3-0».

## Как добавить новую ОС

Допустим, нужна поддержка ROSA Linux.

1. **`detect_os`** — добавьте ветку распознавания перед общей проверкой на Debian:

```bash
elif [ -f /etc/rosa-release ] || [ "$id" = "rosa" ]; then
    OS_ID="rosa"
    OS_PRETTY="$(head -1 /etc/rosa-release 2>/dev/null)"
    OS_VER="$ver"
```

2. **Менеджер и формат** — в `case "$OS_ID"` ниже:

```bash
rosa) PKG_FMT="rpm"; PM="dnf" ;;
```

3. **`parse_args`** — добавьте `rosa` в список допустимых значений `--os`, там же в `detect_os` в проверке `CMD_FORCE_OS`.

4. **`dep_spec`** — если имена пакетов совпадают с РЕД ОС, ничего делать не нужно, общая rpm-ветка подойдёт. Если различаются — добавьте ветку по образцу Альта.

5. **`wayland_pkg_alts`** — имя пакета XWayland для новой ОС.

6. **`check_os_version`** — минимальная поддерживаемая версия.

7. **Обёртка** — скопируйте `update-r7-alt.sh`, замените `PROFILE`.

Проверьте результат: `sudo ./install-r7.sh --os rosa --list-deps`.

## Чего в скрипте нет

Честный список ограничений:

- **Проверка подписи пакета.** MD5 ловит повреждение при скачивании, но не защищает от подмены. GPG-подпись была бы правильнее — нужен публичный ключ Р7.
- **Автоматическая проверка новых версий на сайте.** Сейчас пакеты подкладывают руками или указывают ссылку через `--url`.
- **Откат на предыдущую версию.** Старый пакет удаляется до установки нового. Если новый не встанет, ставить старый придётся вручную из папки.
- **Тесты.** Проверять логику удобно в контейнерах — `docker run -it debian:13` и так по каждой ОС. Автоматических прогонов пока нет.
- **Массовая установка.** Для парка машин пригодился бы режим с чтением списка хостов и запуском по ssh.
